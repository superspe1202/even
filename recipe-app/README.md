# Recipe Glass

Even Realities G2 智慧眼鏡的免手操作食譜 App。

手機負責「選與編」，眼鏡負責「做」：在手機上貼一個網頁或 YouTube 連結、
自動轉成步驟化食譜，下廚時抬頭就能看到現在這一步，不必用髒手碰手機。

## 功能

- **精選台灣料理** — 內建 28 道食譜，可依菜名或食材搜尋、依難易度與分類篩選、依難易度／時間／名稱排序，一鍵加入自己的食譜庫
- **URL 匯入** — 貼上食譜網頁或 YouTube 連結，後端抓內容交給 AI 整理成食材與步驟
- **AI 搜尋食譜** — 打菜名，AI 照常見做法寫一份食譜，看過、改過才存
- **完整編輯** — 新增／刪除食譜，逐項增刪食材，步驟可改寫、排序、刪除
- **採購清單** — 把食譜食材整份加入，同名食材自動併列並保留各自份量與出處，可勾選、可手動增刪，並能推到眼鏡上邊逛超市邊看
- **眼鏡端步驟進度** — 右欄列出步驟清單，目前這步最亮、做完的轉暗、還沒到的居中，抬頭就知道剩幾步
- **眼鏡端標頭時鐘** — 標頭右側顯示現在時間，閒置時每 20 秒自動刷新，不必翻頁也知道現在幾點
- **步驟計時** — 走到要計時的步驟，點一下才開始倒數；開始之後翻到下一步、切去別道菜都照樣在跑，到時間眼鏡閃爍提醒（別道菜的也會響）
- **切換食譜** — 可以同時開著兩道（以上）食譜的進度，眼鏡上長按切到另一道，各自的步驟與計時器都接續，不會重來
- **進度續看** — 中途離開 App 或手機切到背景，回來還在同一步；煮完的菜下次從頭開始
- **眼鏡端操作** — 點擊下一步（遇到計時步驟是開始計時）、上滑上一步、下滑跳過、長按切換食譜、雙擊離開；待命畫面直接教這幾個手勢

## 開發

```bash
npm install
npm run dev          # http://localhost:5173
npm run simulate     # 桌面模擬器
npm run qr           # 產生 QR code，用手機 Even Hub App 掃描上真機
```

「貼上連結」和「AI 搜尋食譜」需要後端。沒設定後端時這兩個按鈕會直接藏起來，
不會讓使用者點進去才看到錯誤。要開啟，先部署 `../worker`（見該目錄的 README），
然後在專案根目錄建立 `.env`：

```
VITE_API_BASE=https://recipe-glass-api.你的帳號.workers.dev
```

同一個網址也要填進 `app.json` 的 `permissions[0].whitelist`，否則 Even 會擋下請求。

## 打包上架

```bash
npm run check-id     # 確認 package_id 未被佔用
npm run pack         # 產生 recipe-glass.ehpk
```

把 `.ehpk` 上傳到 Even Hub 開發者後台送審。

```
├── src/core/              型別、儲存、計時、匯入、食譜庫查詢、採購清單、背景狀態

```

### 幾個關鍵決定

**容器只建立一次。** 啟動時建八個文字容器（標頭／內文／頁尾＋右欄五格，等於單頁純文字
容器的上限），之後一律用 `textContainerUpgrade` 就地更新。`rebuildPageContainer`
每次都整頁閃一下，翻步驟時很難看。

**亮度是韌體功能。** `TextContainerProperty.textColor` 就是文字亮度（0~4，預設 4），
`TextContainerUpgrade` 也吃這個欄位，所以右欄能就地調亮調暗不必重建頁面。

**右欄固定五格，長食譜用視窗捲動。** 不能「有幾步就開幾個容器」—— 純文字容器每頁
上限是 8 個（模擬器上實測撞過：6 格會讓 `createStartUpPageContainer` 回傳 invalid），
而且增減容器只能靠 `rebuildPageContainer`。翻頁時只寫內容或亮度真的變了的格子，
同一步驟內翻頁通常一格都不用動，避免每次五個藍牙往返。

**標頭時鐘用空白撐開右對齊。** 容器沒有文字對齊欄位，只能算出剛好的空白數量把時間
推到最右邊。`getTextWidth` 給起點，但重複幾十個空白時 LVGL 逐字元取整的累積誤差會
跟單次加總的預測不一樣——所以再用 `measureTextWrap` 量真正組出來的那一行，量到會
換行就少一個空白，直到真的放得下一行為止，不是賭一個算出來的數字。標題太長時整個
捨棄時鐘，不硬擠：烹飪資訊永遠優先。

**右欄標籤用真實字寬量測截斷。** 不數字元，因為字寬不等 ——「10 慢燉兩個半小時」
會溢出而「9 慢燉兩個半小時」不會。改用 `measureTextWrap` 逐字退到放得下為止，
換字型或改欄寬都不必重調常數。

**畫面攤平成一維陣列。** 食材頁、每個步驟、完成頁全部攤成一串 `View`，導覽只剩
一個整數索引。進度保存、背景還原、上下頁都變成加減一，不用同時追蹤
「第幾步」和「步驟內第幾頁」兩個狀態。

**計時器跟畫面脫鉤。** 最早的版本是「進入步驟自動開始、離開步驟自動停止」，
實際下廚不是這樣：「燉一小時」開始後會先往下看、先備下一步的料，甚至去顧另一道菜，
一翻頁倒數就消失等於沒用。現在所有計時器放在同一份清單（`RunningTimer[]`），
各自只存絕對結束時間，跟目前顯示哪道菜、哪一步完全無關：翻頁、切菜、切背景、
關掉 App 再開都照跑，到時間才響；響的是別道菜就寫出菜名。頁尾只放得下一個，
顯示最快到的那個，其他用「+N」帶過，不是眼前這步的就標「步驟2」或菜名。

**點一下才開始計時。** 自動開始的問題是：先往後翻看看、還沒開火，時間就已經在跑。
改成走到計時步驟時，頁尾寫「點擊開始計時 5 分鐘 · 下滑跳過」，點擊開始、下滑跳過
（不計時）。只有步驟的最後一頁才會搶點擊，讀到一半不會被打斷；已經開始或已經響過
的步驟點擊就是下一頁，不會按掉「時間到」之後一點又重新計時。

**煮完就清掉進度。** 走到「完成」頁時把這道菜的進度刪掉，否則下次按開始烹飪會直接
跳到「完成了」，食譜庫一直掛著「進行中」，長按還會切回已經煮完的菜。

**切換食譜靠長按，不是新畫面。** SDK 的 `OsEventTypeList` 有 `LONG_PRESS_EVENT`，
跟點擊、雙擊是三種不會互相誤觸的手勢，很適合拿來當「切到另一道」而不用多開
一層選單。進度改成存陣列（`RecipeStore.listProgress`），每道食譜各自一筆
`{recipeId, stepIndex}`；切換時挑「最久沒被更新」的那道接續，只有一道在煮
就什麼都不做，不會誤觸跳走。計時器本來就不綁畫面，切換不用另外處理。

**頁尾提示要看有沒有另一道可以切。** 剛做出長按切換時只顧著寫程式邏輯，
忘了頁尾的操作提示本身還是舊的「點擊下一頁 · 上滑回上頁 · 雙擊離開」，
完全沒提「長按」——功能做出來了但沒人知道怎麼用。補上 `canSwitch` 這個
狀態，`main.ts` 在有進度的食譜集合變動時通知 `GlassesRuntime.setSwitchable()`，
頁尾的提示降級順序（`hintLadder`）依它決定要不要提「長按切換食譜」；
只有一道在煮、或多道都煮完了，提示就照舊不提，不會誤導使用者去長按一個
什麼都不會發生的動作。

**計時器存檔兩份。** 計時器一有變動就寫進 bridge storage（`rg.timers`），背景快照
裡也放一份——快照是同步取的，落盤是非同步的，兩邊都存最保險。App 關著的時候到期
的，重開時 30 分鐘內補響一次，更早的就不響了，免得隔天打開還在閃「時間到」。

**錯誤訊息寫白話。** 使用者看得到的訊息不出現狀態碼、檔名或技術名詞。Worker 把
可以給人看的錯誤（「這部影片沒有字幕」）標成 `UserFacingError` 原樣回傳，其他
（AI 服務掛了、逾時）一律回「整理食譜時出了點問題，請稍後再試」，細節只進 log。

**G2 沒有喇叭**，所以計時結束只能用畫面閃爍提示（整片亮／暗交替約 10 秒）。
這點必須寫進上架說明，否則使用者會以為是故障。

**頁尾不用 ⏱ 符號。** 那是 emoji，韌體字型很可能沒有，而 G2 缺字是靜默略過 ——
不報錯直接消失。改用官方設計文件明列可用的 `━` `─` 畫進度條，還多給一個
「還要等多久」的體感。

**資料一律存 bridge storage。** Even App 是 Flutter WebView，瀏覽器 `localStorage`
與 IndexedDB 在 App 重啟後可能整個消失。長食譜切成 40,000 字一塊分開存。

**AI 輸出一定要正規化。** `src/core/importer.ts` 會把後端回來的東西重新收斂成
合法的 `Recipe`：欄位可能缺、型別可能錯、步驟可能是字串陣列而不是物件陣列。
與其讓眼鏡端渲染時炸開，不如在入口就處理掉。

**採購清單自己做，不接眼鏡內建待辦。** SDK 的 `EvenAppMethod` 列舉只有 17 個方法
（畫面容器、儲存、音訊、IMU、定位、相簿相機），沒有任何筆記或待辦介面 ——
第三方 App 碰不到眼鏡內建功能。所以清單自己存，再用既有的文字容器推到眼鏡上顯示。

**加入食譜是深拷貝。** 從精選料理加入時會重新產生所有 id，之後怎麼改都不影響
內建資料；同一道菜也可以加入兩次分別調整（例如一份加辣一份不加）。

**採購清單不合併份量。** 份量是自由文字（「少許」「3-4 個」）沒辦法數值相加，
所以同名食材各自保留一筆需求與出處，讓使用者自己判斷要買多少。

## 已在模擬器上驗證過

用 `@evenrealities/evenhub-simulator` 的自動化 HTTP API（`/api/screenshot/glasses`
抓真實 576×288 framebuffer、`/api/input` 送觸控事件）實測整份「紅燒牛肉麵」
（12 步）與「珍珠丸子」（含罕見字「荸薺」）從頭走到完成畫面，包括：

- 繁體中文在韌體 LVGL 字型上完整正確渲染，食材、步驟、右欄標籤、標點符號
  （· ● ━ ─）都清晰無缺字
- 單擊事件的 protobuf 零值省略行為與程式碼假設一致（`sysEvent` 沒有 `eventType`
  欄位）
- 右欄視窗捲動、五級亮度轉換、進度條倒數都如預期運作

過程中抓到並修正三個真的 bug（都不是靠猜的，是模擬器截圖 + 像素比對 + 逐步
縮小範圍找出來的）：右欄容器數超過 8 個上限、頁尾文字在特定組合下溢出被裁切、
省略號用了字型不支援的 Unicode 字元。詳見上面對應段落。

## 已知限制

- **背景狀態接的是 host 底層協定。** 官方技能文件提到的 `setBackgroundState` /
  `onBackgroundRestore` 在已發布的 SDK 0.0.15 裡查無此符號，所以
  `src/core/background.ts` 直接實作 `window.__getStateSnapshot` /
  `window.__restoreState`。SDK 補上之後可以換掉這個檔案，對外介面刻意設計成一樣。
- **繁體中文字型未在真機驗證。** 分頁邏輯已用 `@evenrealities/pretext` 依 LVGL
  真實字寬測過（長中文不超行、不掉字），但韌體字型若缺字會**靜默略過**，
  這只有在模擬器或真機上才看得出來。上架前務必實測。
- 匯入功能依賴 `../worker`，沒部署就只能手動新增食譜。
