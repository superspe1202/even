## 一、產品定位

**做菜時不用碰手機的免手操作食譜。**

這是智慧眼鏡最站得住腳的食譜情境：雙手沾滿麵粉、油、生肉的時候，手機是最難用的裝置。把「下一個步驟是什麼」直接放在視線裡，是 G2 相對手機的真正優勢，而不只是把手機 App 搬過去。

### 設計原則

1. **一步一屏** — 眼鏡不是拿來讀完整食譜的，是拿來看「現在這一步」
2. **抬頭即見，低頭做事** — 資訊密度要低，一眼掃完
3. **計時器內建** — 做菜最常見的中斷點就是「等」，計時必須在眼鏡上
4. **手機負責選，眼鏡負責做** — 瀏覽／搜尋／收藏放手機端 WebView，眼鏡端只做執行

## 二、硬體限制對設計的影響

| 限制 | 對食譜 App 的影響 | 因應 |
| --- | --- | --- |
| 576×288、16 階綠 | 無法顯示食物照片的質感 | 眼鏡端**純文字**；照片只放手機端 |
| **沒有相機** | 不能拍食材辨識 | 若要辨識，走 `pickImageFromAlbum`（手機端） |
| **沒有喇叭** | **計時器不能發出聲音** | 計時結束用「畫面閃爍＋文字提示」；這點務必在說明中告知使用者 |
| 非等寬字型、無對齊 | 排版要手動補空白 | 用 `@evenrealities/pretext` 做像素量測 |
| 字型缺字會靜默略過 | **中文食譜有風險** | 上架前必須用模擬器逐字驗證繁體中文字集 |
| 單一容器 2000 字 | 長步驟要分頁 | 沿用 `text-heavy` 範本的預先分頁邏輯 |
| 不能滾動 | 只能翻頁 | 單擊＝下一步、上滑＝上一步 |

> ⚠️ **最高風險項目：繁體中文字型支援。**
> 韌體內建 LVGL 字型若缺字會**靜默略過**，畫面會出現破洞而且不會報錯。開工第一件事就是把預計用到的中文字（食材名、動詞、單位）丟進模擬器實測，並比對 [even-g2-notes](https://github.com/nickustinov/even-g2-notes) 的字元表。**若繁中支援不足，整個產品方向要改為中英並陳或先出英文版。**

### 做不到的事

**接不到眼鏡內建的待辦清單。** SDK 的 `EvenAppMethod` 列舉只有 17 個方法，
全是畫面容器、儲存、音訊、IMU、定位與相簿相機，沒有任何筆記、待辦或提詞機介面
—— 第三方 App 是沙箱隔離的，碰不到眼鏡內建功能。

因應方式：採購清單自己做，再用既有的文字容器推到眼鏡上顯示。使用情境一樣
（逛超市抬頭看要買什麼），而且不受制於別人的 API 變動。

**抓不到 Google 搜尋最上面的 AI 回答。** 那是 Google 網頁自己的介面
（AI Overview），沒有公開 API，爬蟲抓會違反服務條款，而且畫面隨時會改版、
很容易抓壞。

因應方式：「AI 搜尋食譜」改成直接請後端的 AI 憑自己的知識生成食譜，達到
同樣的最終體驗（打幾個字、AI 生出食譜、確認後才存），只是不真的上網搜尋。

### 尚未實作

- **語音控制**（`g2-microphone`）：「下一步」「重複」「計時五分鐘」—— 真正的免手操作終局
- 收藏／最近煮過的分類
- 個人食譜匯出入
- IMU 點頭手勢翻頁（雙手全髒時的備案）

## 四、系統架構

```
            手機 Even Hub App（WebView）
            ├─ 食譜庫 / 編輯器 / URL 匯入
            └─ SDK bridge ──藍牙──> G2 眼鏡（LVGL 渲染）
                    │
                    │ 只對這一個網域發請求
                    ▼
            Cloudflare Worker（你自己的）
            ├─ 抓網頁 HTML → 轉純文字
            ├─ 抓 YouTube 字幕
            └─ 呼叫 AI（OpenAI 相容端點）→ 結構化食譜 JSON
                    │
                    ▼
            Gemini API（OpenAI 相容端點）
            可換成 OpenAI / Groq / 自架，只改兩個環境變數
```

### 為什麼一定要有後端

這不是為了架構好看，是兩個硬性前提：

1. **金鑰不能放前端。** 上架的 `.ehpk` 任何人都能解壓縮，AI API key 放進去等於公開。
2. **CORS 擋住第三方網站。** `app.json` 的 network 白名單是 Even 層級的權限檢查，
   **不會繞過瀏覽器 CORS**。絕大多數食譜網站不發 `Access-Control-Allow-Origin`，
   前端直接 `fetch` 必定失敗。

好處是：抓取集中在後端之後，App 只跟一個網域說話，`app.json` 的白名單只需要列
一個位址 —— 送審時反而最乾淨。

### 專案結構

```
recipe-app/               G2 App（Vite + TypeScript）
├── app.json              上架資訊清單
├── src/core/             型別、儲存、計時、匯入正規化、背景狀態
├── src/glasses/          版面、分頁、執行時期
└── src/phone/            食譜庫、匯入、編輯器
worker/                   Cloudflare Worker
├── src/index.ts          路由、CORS、AI 呼叫
├── src/readable.ts       HTML → 純文字
└── src/youtube.ts        字幕抓取
```

## 五、眼鏡端畫面（576×288）

```
┌──────────────────────────────┬──────────────┐ 576×288
│ 番茄炒蛋 · 步驟 2/6           │              │ header 576×32  亮度 3
├──────────────────────────────┼──────────────┤
│ 炒蛋至七分熟。                │ 1 番茄切滾刀塊│ ← 亮度 1（做完）
│ 油要多一點，潤過後轉小火下蛋。 │ 2 熱鍋多油   │ ← 亮度 4（目前）
│                              │ 3 原鍋補油   │ ← 亮度 2（未到）
│ ● 蛋不要炒太老                │ 4 加番茄醬…  │
│                              │ 5 蛋回鍋拌勻 │
│ body 400×214  內框 392×206   │ 6 起鍋前撒…  │ rail 168×30 ×6
│ 7 行  isEventCapture: 1      │              │
├──────────────────────────────┴──────────────┤
│ 02:34 ━━━━━━────  ·  點擊下一頁              │ footer 576×34  亮度 2
└─────────────────────────────────────────────┘
```

共 9 個容器（上限 12）。亮度對應 SDK 的 `textColor`（0~4），`TextContainerUpgrade`
也吃這個欄位，所以能就地調亮調暗不必重建頁面。

| 手勢 | 事件 | 動作 |
| --- | --- | --- |
| 單擊 | `CLICK_EVENT`（封包裡沒有 eventType） | 下一頁 |
| 上滑 | `SCROLL_TOP_EVENT` (1) | 上一頁 |
| 下滑 | `SCROLL_BOTTOM_EVENT` (2) | 下一頁 |
| 雙擊 | `DOUBLE_CLICK_EVENT` (3) | `shutDownPageContainer(1)` 離開 |

計時結束時，內文在「時間到」與空白之間每 600ms 交替約 10 秒，或直到使用者點擊。
**G2 沒有喇叭，這是唯一能引起注意的手段**，上架說明必須明講。

頁尾的計時不用 ⏱ —— 那是 emoji，韌體字型很可能沒有，缺字會靜默消失。改用官方
設計文件明列可用的 `━` `─` 畫進度條。

## 六、關鍵設計決定

**容器只建立一次。** 啟動時建三個容器，之後一律 `textContainerUpgrade` 就地更新。
`rebuildPageContainer` 每次都整頁閃一下，翻步驟時很難看。

**畫面攤平成一維陣列。** 食材頁、每個步驟、完成頁攤成一串 `View`，導覽只剩一個整數
索引 —— 進度保存、背景還原、上下頁都變成加減一。

**點一下才開始計時，計時器跟畫面脫鉤。** 最早是進入步驟自動起算、離開自動停止，
但「煮 5 分鐘」時人本來就會翻去看下一步，一翻頁倒數就消失等於沒用；自動開始也會在
還沒開火時就先跑。現在走到計時步驟時點擊開始、下滑跳過，開始之後翻頁、換菜都照跑。
手機上也看得到所有倒數、也能直接按開始，雙手髒的時候交給旁邊的人按也行。

**食材清單另走行打包器。** 段落導向的分頁器會讓「食材（2 人份）」標題自己佔一頁，
所以清單改用 `paginateLines` 以行為單位打包。

**AI 輸出一定要正規化。** 模型可能漏欄位、給錯型別、把步驟給成字串陣列。
`src/core/importer.ts` 在入口就收斂成合法 `Recipe`，而不是讓眼鏡端渲染時炸開。

## 七、驗證狀態

已實測通過：

- `npm run build` 建置成功（225 KB / gzip 70 KB）
- `tsc --noEmit` 型別檢查無誤（App 與 Worker）
- `evenhub pack` 產出 `.ehpk`（78 KB），無警告
- 中文分頁：長中文段落不超出 7 行上限、分頁後可完整還原不掉字
- 右欄 19 項測試：視窗捲動、亮度分級、開頭與結尾貼齊、標籤不換行、寫入次數
- 28 道食譜在所有步驟位置的右欄標籤都不換行（`fitLabel` 用 `measureTextWrap` 逐字退到放得下為止，結構上保證不換行）；左欄縮到 392px 後仍全部在 7 行內
- HTML 轉文字：正確移除 script/style/nav/footer、食材保持分行、HTML 實體正確解碼
- YouTube 字幕軌解析：標題含中括號與跳脫引號時仍正確切出、人工字幕優先於自動字幕、
  壞掉的 JSON 不丟例外

**已用模擬器驗證：**

用官方 `evenhub-simulator` 的自動化 API 實測整份食譜從食材到完成畫面，
抓到並修正三個真的 bug：

1. 右欄一開始做 6 格，撞到「純文字容器最多 8 個」的上限
   （`createStartUpPageContainer` 回傳 1 = invalid），改成 5 格
2. 頁尾在「長時間格式 + 滿版進度條 + 完整提示」的組合下會超出一行寬度，
   LVGL 不會自動換行，整段被悄悄裁掉；改成用 `measureTextWrap` 量測後
   依優先序降級
3. 省略號用「…」（U+2026）在這個韌體字型裡量得到寬度但畫出來是一條細線，
   不是三個點；換成 ASCII 的 `...` 後正確顯示 —— 全食譜庫有 320 處會
   觸發這個截斷，影響範圍不小

繁體中文本身（食材、步驟、標點符號）在模擬器上完整正確渲染，沒有缺字。

**尚未驗證（模擬器與真機仍有已知差異）：**

- **真機的實際字型顯示。** 模擬器 README 自己也說「字型渲染可能與硬體不完全
  一致」，模擬器測試能抓出「明顯錯誤」（如這次的省略號），但無法完全排除
  真機特有的差異。
- 藍牙延遲下的翻頁手感
- 完整煮一道菜的端到端流程（含真人操作觸控板）

## 八、上架準備

### `app.json` 現況

```json
{
  "package_id": "com.superspe.recipeglass",
  "edition": "202601",
  "name": "Recipe Glass",
  "version": "0.1.0",
  "min_app_version": "2.2.10",
  "min_sdk_version": "0.0.15",
  "entrypoint": "index.html",
  "permissions": [
    { "name": "network", "desc": "...", "whitelist": ["https://你的-worker.workers.dev"] }
  ],
  "supported_languages": ["zh", "en"]
}
```

`min_app_version` 是 2.2.10 而非文件範例的 2.0.0 —— 那是 SDK 0.0.15 的實際下限，
填低了 `evenhub pack` 會自動改寫並發出警告。
