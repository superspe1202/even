## 一、產品定位

**做菜時不用碰手機的免手操作食譜。**

這是智慧眼鏡最站得住腳的食譜情境：雙手沾滿麵粉、油、生肉的時候，手機是最難用的裝置。把「下一個步驟是什麼」直接放在視線裡，是 G2 相對手機的真正優勢，而不只是把手機 App 搬過去。

### 設計原則

1. **一步一屏** — 眼鏡不是拿來讀完整食譜的，是拿來看「現在這一步」
2. **抬頭即見，低頭做事** — 資訊密度要低，一眼掃完
3. **計時器內建** — 做菜最常見的中斷點就是「等」，計時必須在眼鏡上
4. **手機負責選，眼鏡負責做** — 瀏覽／搜尋／收藏放手機端 WebView，眼鏡端只做執行

## 二、硬體限制對設計的影響

| 限制 | 對食譜 App 的影響 | 因應 |
| --- | --- | --- |
| 576×288、16 階綠 | 無法顯示食物照片的質感 | 眼鏡端**純文字**；照片只放手機端 |
| **沒有相機** | 不能拍食材辨識 | 若要辨識，走 `pickImageFromAlbum`（手機端） |
| **沒有喇叭** | **計時器不能發出聲音** | 計時結束用「畫面閃爍＋文字提示」；這點務必在說明中告知使用者 |
| 非等寬字型、無對齊 | 排版要手動補空白 | 用 `@evenrealities/pretext` 做像素量測 |
| 字型缺字會靜默略過 | **中文食譜有風險** | 上架前必須用模擬器逐字驗證繁體中文字集 |
| 單一容器 2000 字 | 長步驟要分頁 | 沿用 `text-heavy` 範本的預先分頁邏輯 |
| 不能滾動 | 只能翻頁 | 單擊＝下一步、上滑＝上一步 |

> ⚠️ **最高風險項目：繁體中文字型支援。**
> 韌體內建 LVGL 字型若缺字會**靜默略過**，畫面會出現破洞而且不會報錯。開工第一件事就是把預計用到的中文字（食材名、動詞、單位）丟進模擬器實測，並比對 [even-g2-notes](https://github.com/nickustinov/even-g2-notes) 的字元表。**若繁中支援不足，整個產品方向要改為中英並陳或先出英文版。**

## 三、功能規劃

### v1.0（首次上架目標）

| 功能 | 眼鏡端 | 手機端 |
| --- | --- | --- |
| 食譜清單 | 顯示已選食譜名稱 | 卡片列表、搜尋、分類 |
| 步驟導航 | **主畫面**：步驟 n/N + 內容 | 同步顯示目前步驟 |
| 食材清單 | 開始前一屏總覽 | 可勾選的採買清單 |
| 計時器 | 倒數顯示 + 結束提示 | 可調整時間 |
| 進度保存 | `setLocalStorage` 記住中斷位置 | — |
| 收藏 | — | 收藏／最近煮過 |

**v1.0 刻意不做網路連線** —— 食譜內建在套件裡。理由：

- `permissions: []` 零權限，**審核最快、使用者信任成本最低**
- 避開 CORS 地雷（見研究文件第三節）
- 做菜現場常在廚房角落，網路不見得穩

### v1.1+（上架後迭代）

- **語音控制**（`g2-microphone`）：「下一步」「重複」「計時五分鐘」→ 這才是真正的免手操作終局
- 雲端食譜庫（需 `network` 權限 + 自架 Cloudflare Worker 解 CORS）
- 個人食譜匯入
- IMU 點頭手勢翻頁（雙手全髒時的備案）

## 四、眼鏡端畫面設計（576×288）

### 主畫面：步驟執行

```
┌────────────────────────────────────────────┐ 576×288
│ 蔥油雞                          步驟 3/8   │  ← 標頭 576×32
├────────────────────────────────────────────┤
│                                            │
│  雞腿肉下鍋，皮面朝下                       │  ← 內文 576×200
│  中火煎 5 分鐘至金黃                        │     行高 27px ≈ 7 行
│                                            │
│  ● 不要翻動                                 │
│                                            │
├────────────────────────────────────────────┤
│ ⏱ 04:32   ▶ 點擊下一步                      │  ← 頁尾 576×56
└────────────────────────────────────────────┘
```

**容器配置**（上限 12 個，這裡只用 3 個，很寬裕）：

| ID | name | 位置 | 尺寸 | 用途 |
| --- | --- | --- | --- | --- |
| 1 | `header` | (0,0) | 576×32 | 食譜名 + 進度 |
| 2 | `body` | (0,32) | 576×200 | 步驟內容（`isEventCapture: 1`） |
| 3 | `footer` | (0,232) | 576×56 | 計時器 + 操作提示 |

### 操作對應

| 手勢 | 事件 | 動作 |
| --- | --- | --- |
| 單擊 | `CLICK_EVENT`（無 eventType！） | 下一步 |
| 上滑 | `SCROLL_TOP_EVENT` (1) | 上一步 |
| 下滑 | `SCROLL_BOTTOM_EVENT` (2) | 下一步 |
| 雙擊 | `DOUBLE_CLICK_EVENT` (3) | `shutDownPageContainer(1)` 離開 |

計時器啟動改為「長按替代方案」：因為觸控板沒有長按事件，v1.0 設計為**步驟資料自帶計時秒數**，進入該步驟自動起算，單擊進下一步時自動停止。使用者不需要額外操作。

### 計時結束提示（無喇叭的因應）

```
┌────────────────────────────────────────────┐
│ 蔥油雞                          步驟 3/8   │
├────────────────────────────────────────────┤
│                                            │
│         ⏱  時 間 到                         │  ← 每 500ms 切換
│                                            │     滿版／空白造成閃爍
│         煎 5 分鐘 已完成                    │
│                                            │
├────────────────────────────────────────────┤
│ ▶ 點擊繼續                                  │
└────────────────────────────────────────────┘
```

閃爍持續約 10 秒或直到使用者點擊。**上架說明必須明確寫出「計時器為視覺提示，無聲音」**，避免使用者誤以為故障而給負評。

## 五、技術選型

| 項目 | 選擇 | 理由 |
| --- | --- | --- |
| 起始範本 | **`text-heavy`** | 食譜本質是長文分頁，分頁邏輯與 `pretext` 量測可直接沿用 |
| 建置 | Vite + TypeScript | 官方範本標準 |
| 分頁 | `@evenrealities/pretext` | 像素級量測，避免中文被截斷 |
| 狀態保存 | `bridge.setLocalStorage` | 瀏覽器 localStorage 在 Flutter WebView 不可靠 |
| 背景保存 | `setBackgroundState` / `onBackgroundRestore` | 手機切背景時計時器與步驟不能重置 —— **食譜 App 必做** |
| 食譜資料 | 內建 JSON | v1.0 零權限 |

### 專案結構規劃

```
recipe-app/
├── app.json                 # 上架資訊清單
├── index.html               # 手機端 WebView 宿主
├── src/
│   ├── main.ts              # 入口、bridge 初始化、事件路由
│   ├── glasses/
│   │   ├── layout.ts        # 三容器建立與更新
│   │   ├── screens.ts       # 食材屏／步驟屏／計時屏
│   │   └── paginate.ts      # 步驟文字分頁（改自 text-heavy）
│   ├── phone/
│   │   └── ui.ts            # 手機端食譜瀏覽介面
│   ├── core/
│   │   ├── recipe.ts        # 食譜型別與載入
│   │   ├── timer.ts         # 計時器
│   │   └── storage.ts       # setLocalStorage 封裝
│   └── data/
│       └── recipes.json     # 內建食譜
└── vite.config.ts
```

### 食譜資料格式

```ts
interface Recipe {
  id: string
  name: string          // 眼鏡端標頭用，建議 ≤ 10 字
  servings: number
  totalMinutes: number
  ingredients: { item: string; amount: string }[]
  steps: {
    text: string        // 建議 ≤ 120 字，一屏可讀完
    timerSeconds?: number
    tip?: string
  }[]
}
```

## 六、上架準備

### `app.json` 草案

```json
{
  "package_id": "com.superspe.recipeglass",
  "edition": "202601",
  "name": "Recipe Glass",
  "version": "1.0.0",
  "min_app_version": "2.0.0",
  "min_sdk_version": "0.0.12",
  "entrypoint": "index.html",
  "permissions": [],
  "supported_languages": ["zh", "en"]
}
```

> `name` 上限 20 字元；`package_id` 只能小寫字母與數字（不可有連字號），故用 `recipeglass` 而非 `recipe-glass`。

### 上架前檢查清單

- [ ] 繁體中文字型在模擬器逐字驗證通過（**最優先**）
- [ ] `npx evenhub pack app.json dist -c` 確認 `package_id` 未被佔用
- [ ] 所有步驟文字在 576×200 容器內不被截斷
- [ ] 手機切背景再回來，步驟與計時器狀態正確還原
- [ ] 雙擊在任何畫面都能離開 App
- [ ] 真機（QR 掃描）實測完整煮一道菜的流程
- [ ] 上架說明註明「計時器為視覺提示，無聲音」
- [ ] `npm run build` 後 `dist/index.html` 存在

## 七、建議執行順序

| 階段 | 工作 | 產出 |
| --- | --- | --- |
| 0 | **中文字型驗證** | 可用字集報告，決定語言策略 |
| 1 | `degit` 建立 text-heavy 專案骨架 | 可在模擬器跑的空殼 |
| 2 | 食譜資料格式 + 3 道測試食譜 | `recipes.json` |
| 3 | 眼鏡端三容器佈局與步驟導航 | 可翻步驟的原型 |
| 4 | 計時器 + 視覺提示 | 完整執行流程 |
| 5 | 背景狀態保存 + 進度續看 | 穩定性達標 |
| 6 | 手機端瀏覽／收藏介面 | 完整 App |
| 7 | 真機測試 + 打包送審 | `.ehpk` |

階段 0 是 gate：中文字型結果會決定後面全部的內容策略，所以必須先做。
